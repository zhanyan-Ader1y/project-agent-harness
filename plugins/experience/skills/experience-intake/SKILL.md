# experience-intake

把刚才那次踩坑变成一条团队共享的经验。

## 一条不可让渡的规矩

**产出经验的人不能同时裁决它。**

腾讯团队的初版正是"抽取即入库"，**约 90% 是废经验**；他们的结论是「让 AI 自己判断自己产出经验的价值，等于让裁判同时当运动员」。所以这个 skill **不做准入判定的全部**——它只做机器判不了的那一半，剩下的由 `scripts/experience-write.js` 强制。

| 谁判 | 判什么 |
| --- | --- |
| **你（本 skill）** | 这值不值得记（三镜头）、它是不是垃圾（九类）、代价是不是高到一次就该记（乙分支的信号与锚） |
| **脚本** | 形状、红线、evidence 真的跑不跑得通、符号真的存不存在、库里有没有同型条目、这条该是 candidate 还是 confirmed |

**你不判"库里有没有同型条目"。** 那需要查库，而查库的结果决定它进不进检索——判断权在有执行者的那一层。

## 步骤

### 1. 先过 Review

按 [`review.md`](review.md) 逐项判。**三镜头一个都不命中就到此为止，不要记**——无论它多高频、代价多大。

### 2. 写出条目

一个 JSON 对象。**所有 metadata 取值只能是字符串或字符串数组**（mem0 只存字符串，数字往返后变成字符串，`"0" !== 0` 会让这条经验此后每次校验都判失败）。

```json
{
  "information": "一句话：什么做法导致什么错误",
  "metadata": {
    "repo": "仓库名", "commit": "当前 commit",
    "author": "谁写的", "at": "YYYY-MM-DD",
    "lens": "blackword | index | logic",
    "symbols": ["ZzWidget.attachToList"],
    "files": ["src/widget.js"],
    "evidence_cmd": "能复现或证伪它的命令",
    "evidence_exit": "1",
    "evidence_contains": ["报错里的特征串"]
  }
}
```

**`symbols` 与 `files` 至少要有一个**——注入前的机器校验靠它们，两者皆空的条目谁也验不了，写进去也永远不会被采信。

**`symbols` 写限定名**（`ZzWidget.attachToList`，不是 `attachToList`）。只写末段会让同型判定认不出它，也可能和别的类的同名方法混在一起。

**`evidence_cmd` 会被真的执行。** 写一条在你自己机器上跑得通的命令；期望非零退出码时必须显式写 `evidence_exit`，否则等于声称 `"0"`，会被判失败。

### 3. 判断走不走乙分支

默认不走。只有满足 [`merge.md`](merge.md) 里那五条信号之一、**且**你能给出对应的锚时，才加上 `high_cost` 与 `high_cost_anchor`。

**锚必须是你无法自由撰写的东西**——用户的逐字原话、真实的退出码、真实的 run id。取不到锚就不要走乙分支，退回去存候选。

### 4. 交给脚本

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/experience-write.js" - <<'JSON'
{ …条目… }
JSON
```

先跑一次 `--dry-run` 看它会写什么，确认无误再去掉这个选项。

**退出码非 0 就是没写进去。** 不要重述成"已记录"——脚本会把原因打在 stdout 的 `detail` 里，照实告诉用户。常见的三类：

| 报什么 | 怎么办 |
| --- | --- |
| 缺 `MEM0_USER_ID` / `MEM0_API_KEY` | 配置问题，让用户按插件 README 配上，不是你能修的 |
| 条目声称的仓库与当前仓库不符 | 经验只能由身处该仓库的人写下，换个地方写 |
| 自检未通过（符号查无踪迹 / 命令跑不通） | **多半是经验本身错了**，回到第 2 步改，不要放宽断言绕过去 |

## 三条硬约束

**不得自带 `status`、`occurrences`、`promoted_from`。** 它们是脚本的产出。自带 `status: confirmed` 等于把自己的经验直接送进每个人的上下文，那正是这个 skill 存在要防的事——脚本会拒绝，别去试。

**不要用 mem0 的 `add_memory` / `update_memory` / `delete_*` 工具。** 有一条 hook 会拒绝它们。写入只能走脚本，因为查库、红线过滤与硬失败都落在脚本里。检索类工具不受影响，随便用。

**放宽断言不是修复。** 自检不通过时把 `evidence_contains` 删掉、把符号改成一个确实存在的无关标识符，条目就能写进去了——但它从此是一条没人能证伪的断言，还会以权威姿态进入每个人的上下文。**一条错误的经验比没有经验更贵。**

## 撤回

发现一条已入库的经验是错的：把它原样取回来，改 `status` 为 `retracted`，走同一个脚本写回。检索会排除它。

**撤回不需要审批。** 没有撤回路径的话，一条错误的 `confirmed` 会被每轮注入，而它删不掉（hook 拒绝）、评审不了（没有 diff）、也追不了责（`author` 是自填的）。
