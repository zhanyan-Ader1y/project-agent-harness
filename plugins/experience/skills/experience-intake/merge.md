# Merge：这条该不该进入检索

过了 Review 只说明它是一条经验，不说明它够格进每个人的上下文。

**只有 `status: confirmed` 会被检索到。** `candidate` 存在库里但不注入。

两条路进 `confirmed`，**你只负责其中一条**。

## 甲——重复出现（脚本判，你不判）

官方实践的原话是"Claude 犯错两次，更正就写进 `CLAUDE.md`"，但**那条规则的执行者是人**。写入路径里没有人，跨会话、跨成员都无从知道这是第几次。

所以"是不是第二次"**从记忆问题改成了查询问题**：脚本查库，查不到写 `candidate`，查得到就 `occurrences + 1` 并翻成 `confirmed`。

**你不要替它猜。** 具体地说：

- 不要因为"我记得这个坑之前提过"就自带 `status: confirmed`——脚本会拒绝
- 不要为了让它匹配上而去改 `symbols` 或 `files`
- 不要因为查库可能查不到就把一条经验写两遍

**第一次写进去是 `candidate` 是正确结果，不是失败。** 它在库里等下一个人撞上。

## 乙——单次高代价（你判）

有些坑代价高到一次就该记。但"代价高"是个可以随口声称的东西，所以**每条信号必须绑一个你无法自由撰写的锚**。

| 信号（填进 `high_cost`） | 必附的锚（填进 `high_cost_anchor`） |
| --- | --- |
| `corrected` 人纠正过 | 用户原话**逐字引用** + 是第几轮 |
| `repeated_failure` 同一条命令连续失败 ≥ 3 次 | 三次的命令与退出码 |
| `outside_workspace` 产生了工作区之外的影响 | 具体动作与目标 |
| `gate_denied` 被闸门拒绝过 | 被拒的 hook 名与时间 |
| `broke_tests` 弄坏了已通过的测试或 CI | run id 或命令退出码 |

**取不到锚就不许走乙分支，退回去存候选。**

为什么锚是必需的：形状检查只能验证"字段存在且取值在枚举内"，验证不了它为真。前身项目实测过精确的反例——详细设计把 Agent 自己的推论包装成人类评审者的要求，**引用格式完全合规，只是批复原话里根本没有那句**，静态检查与人工通读都放得过去。

由此得出的规矩，这里同样适用：**凡声称某项决定来自人类，都必须可追溯到逐字原话；追溯不到即拦。**

`gate_denied` 有一条例外：**本插件自己的闸门不算**。否则"我写记录被拒了"会自我指涉地构成一条经验。

## 乙分支的代价，知情后再用

乙分支一次入检索，它的全部过滤就只有三镜头、九类垃圾和 `assert-replay` 三道——**少了"另一个人也撞上过"这个最强的信号**。

所以：**拿不准就走甲分支。** 存成候选的成本是"下一个人撞上时它才生效"；误走乙分支的成本是一条只有你觉得重要的经验进了所有人的每一轮上下文。
