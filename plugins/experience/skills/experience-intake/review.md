# Review：值不值得记

两道，顺序不能反。**第一道不过就到此为止，不必看第二道。**

## 第一道：这是"经验"吗

> **如果 Agent 自己就能推出来，召回它没有任何额外价值。**

按**认知障碍**分类，不按主题或重要性——那两个维度要么列不完，要么全凭主观；"Agent 能不能自己发现"是**客观可判定的**。

| 镜头 | 障碍本质 | 判据 |
| --- | --- | --- |
| **blackword**（黑话） | 语义不可发现 | 项目内部的缩写、代称，字面完全无法推导 |
| **index**（索引） | 位置不可发现 | 某能力的入口不在直觉路径上，读代码找不到，得知道"去哪找" |
| **logic**（逻辑） | 行为不可发现 | 反直觉的工程约束、隐式机制，常规推理推不出来 |

**三个都不命中就不记录**，无论它多高频、代价多大。命中哪个就填进 `lens`——**缺 `lens` 脚本直接拒收**。

判不准时问一句：**一个没读过这个项目、但很会写代码的人，会不会栽在同一个地方？** 不会，就不是经验。

## 第二道：九类垃圾

任何一类命中即不记录。这九类是把垃圾率从 90% 打到 5% 的起点——**先研究垃圾再反推好经验**，因为"好经验"难一次定义到位，垃圾的特征却容易归纳。

| 特征 | 说明 |
| --- | --- |
| 事实性错误 | 编造不存在的约束，把对话里的临时说法当规则 |
| 通用常识 | 任何项目都适用，不体现团队特异性 |
| 对话摘要 | 只复述过程，没有沉淀成可复用的判断 |
| 一次性 case | 只对当前任务有效，不能迁移 |
| 用户主观偏好 | 个人选择，不代表团队规范 |
| 缺少上下文 | 不知道对应哪个模块、组件、接口 |
| 粒度混用 | 一条里既有通用规则又有 case 特定信息 |
| 不可执行 | 只有抽象建议，看完不知道怎么做 |
| 证据不足 | 对话里没有足够依据，自己推断过多 |

**「事实性错误」这一类不靠读文本判。** 它交给 `assert-replay`：符号真的存不存在、命令真的跑不跑得通。你要做的是**把 `symbols` 与 `evidence_cmd` 填对**，让它有东西可查——填不出来，本身就说明证据不足。

**「粒度混用」最常见的形态**是把"这个项目里 X 要这样做"和"这次任务里我改了 Y"写进同一条。拆成两条，后者多半是一次性 case，不该记。

## 每条经验必须自证

写完之后，这三项你要能当场答出来，答不上就是还没通过 Review：

- **为什么这是经验**——命中哪个镜头，解决了什么可复用的问题
- **通过了哪些垃圾检查**——上面九类里最容易沾的是哪几类，为什么不沾
- **证据是什么**——哪几轮对话、哪条命令的输出支撑它

**第三项最容易糊弄过去。** "证据是我们刚才试过了"不是证据；"跑 `npm test -- widget` 会看到 `attachToList is not a function`"才是——后者能写进 `evidence_cmd`，前者不能。**写不出 `evidence_cmd` 的经验，多半是"证据不足"那一类。**
